# LoL Scrim Bot

Discord-бот для организации скримов и кастомок по League of Legends: панель выбора линий,
сбор состава, жеребьёвка капитанов, деление на команды и драфт.

## Возможности

| Команда | Что делает |
| --- | --- |
| `/roles` | Публикует панель с кнопками выбора линий (Top / Jungle / Mid / ADC / Support). Кнопка выдаёт роль, повторное нажатие снимает её. Только для тех, у кого есть право «Управлять ролями». |
| `/lanes` | Показывает, кто на какой линии играет, по выданным ролям. |
| `/scrim` | Сбор на скрим против другой команды: кнопки «Играю», «Запасной», «Не смогу», счётчик до 5 человек. Сверх нормы в состав не пускает — опоздавшие уходят в запас. Объявление по умолчанию пингует @everyone (параметр `ping`). Записи сохраняются на диск и переживают перезапуск контейнера. |
| `/custom` | Сбор на кастомку 5×5 — то же лобби, но счётчик до 10 человек. Объявление по умолчанию пингует @everyone (параметр `ping`). Когда состав собран, включается цепочка кнопок: «Заролить капитанов» → «Начать драфт» → «Раскидать по каналам». Сыграли катку — «🔁 Новая раздача» (автор сбора или организатор): составы те же, линии и чемпионы заново по тому же режиму, чемпионы прошлой катки не повторяются. В «Классике» кнопки нет — там бот ничего не раздаёт. |
| `/roster` | Показывает состав последнего открытого сбора. |
| — | Время сбора пишется как удобно: «сегодня 21:00», «завтра в 19», «пт 20:30», «29.09 21:00». Бот превращает его в настоящую дату Discord — каждый видит её в своём часовом поясе, с обратным отсчётом. За 15 минут до начала бот тегает записавшихся (`REMIND_MINUTES`). |
| — | Серии: у `/custom` есть параметр `series` — Bo1, **Bo3 (по умолчанию)** или Bo5. После **каждой** катки организатор жмёт «Победили синие / красные»: в посте виден счёт серии (🔵 2 : 1 🔴), бот объявляет, кто взял серию, а каждая катка идёт в статистику. Составы между катками те же; «Новая раздача» — только если нужны новые линии и чемпионы. Ошиблись кнопкой — «Отменить результат» в ответе бота. |
| `/stats` | Статистика игрока: катки, победы, винрейт, Elo, сколько раз MVP, место на сервере. |
| `/leaderboard` | Таблица лидеров (от 3 каток), порядок по Elo. |
| — | **Elo**: у всех старт 1000. За победу над более сильной командой дают больше, над слабой — меньше (считается по среднему Elo команд). Первые 10 каток Elo меняется быстрее. По Elo делятся команды в режиме «по силе». Отмена результата возвращает Elo точно. |
| — | **MVP**: после каждой отмеченной катки бот запускает голосование (10 минут, `MVP_VOTE_MINUTES`): голосуют только игравшие, за себя нельзя. MVP видно в `/stats` и таблице лидеров. |
| — | **Приглашение на кастомку**: если к 17:00 (`LOBBY_INVITE_HOUR`) сбора на сегодня нет, Олег зовёт всех в канал объявлений с кнопкой «Я бы сыграл» и ссылкой на `/custom`; когда желающих 10 — тегает их. Раз в день. |
| — | **Результат по скриншоту**: игрок или организатор кидает скриншот таблицы итогов в канал сбора — Олег (через Gemini, он видит картинки) угадывает победившую сторону по чемпионам из раздачи и никам, хвалит лучший KDA, подкалывает того, кто больше всех умирал, и предлагает кнопки «Победили синие/красные». Записывает результат только автор сбора или организатор. Нужен `GEMINI_API_KEY`. |
| — | **Итоги недели**: по субботам в 11:00 (`RECAP_WEEKDAY`, `RECAP_HOUR`) Олег публикует номинации — больше всех каток, лучший винрейт, серия побед, рост Elo, MVP недели — со своим комментарием. Канал — `ANNOUNCE_CHANNEL_ID` или тот, где отмечали последнюю катку. Если каток за неделю не было — молчит. |
| — | Кто-то из состава нажал «Не смогу» или «Убрать мой голос» — его место сам занимает первый запасной, бот его тегает. Работает, пока составы ещё не поделены на команды. |
| `/ping` | Зовёт тех, кто записался на последний открытый сбор, вместо @everyone. Параметр `who`: состав (по умолчанию), состав и запасные, только запасные; `text` — что дописать к пингу. Доступна организатору сбора и тем, кто в нём записан. |
| — | Организатор правит состав кнопкой «Правка состава»: убрать из сбора, отправить в запас, вернуть в состав. Кнопка «Отменить кастомку» закрывает сбор. |
| — | В самом посте сбора: капитаны выбираются случайно из набранного состава, затем они по очереди разбирают игроков (1-2-2-1), а готовые составы разводятся по двум голосовым каналам. Управляет ходом автор сбора или организатор ивентов; выбирают игроков сами капитаны. |
| — | Кнопка «Режим» в посте сбора (для организатора) — выбор режима игры перед запуском: готовый пресет или настройка по трём пунктам. Команды: капитанский драфт, случайные, по отмеченным линиям, по силе (статистике). Линии: свободно, случайно, свои, не своя роль. Чемпионы: свободно, 3 на выбор, один случайный, зеркало. После запуска бот публикует «раздачу»: команды, линии и чемпионов с правилами банов и картинкой с портретами выпавших чемпионов. Драфт в посте сбора переживает перезапуск бота; если капитаны 15 минут никого не выбирают, драфт закрывается и его можно перезапустить. |
| `/captains` | Случайно выбирает капитанов из голосового канала (по умолчанию двух — на синюю и красную стороны). Есть кнопки «Перебросить» и «Начать драфт». |
| `/draft` | Драфт: капитаны по очереди набирают игроков из общего списка в порядке 1-2-2-1. |
| `/teams` | Делит голосовой канал на две команды. С параметром `by_lanes` пытается собрать два состава по линиям, опираясь на роли игроков. |
| `/split` | Разводит последние сформированные составы по двум голосовым каналам. |
| `/side` | Разыгрывает стороны — синие или красные. |
| `/pick-player` | Выбирает случайного человека из голосового канала (кому первый бан, кто ведёт пик и т. д.). |
| `/champion` | Случайный чемпион с актуального патча (данные Riot Data Dragon). |
| `/champion-roll` | Раздаёт каждому в голосовом канале случайного чемпиона. |
| `/lane-roll` | Раздаёт линии случайным образом, не глядя на роли. |

## Режимы игры

| Режим | Команды | Линии | Чемпионы |
| --- | --- | --- | --- |
| 👑 Классика | капитанский драфт | договариваетесь сами | свободно |
| 🎲 Полный рандом | случайно | случайно | свободно |
| 🃏 Рулетка трёх | случайно | случайно | 3 на выбор на свою линию |
| 🧭 По своим линиям | подбор под отмеченные линии | свои | свободно |
| 🙃 Не своя роль | случайно | туда, где игрок не играет | 3 на выбор |
| 🪞 Зеркало | случайно | случайно | соперники по линии играют одним чемпионом |
| 🌪️ Хаос | случайно | случайно | один случайный |
| ⚖️ Честный бой | уравнены по статистике побед | свои | свободно |

Чемпионы в раздаче не повторяются на всю кастомку. Бот помнит, кто когда выпадал на сервере (`data/champion_history.json`), и выбирает случайно среди давно не выпадавших — примерно трети списка линии, поэтому одни и те же чемпионы не мелькают из игры в игру. Баны обычные (лобби «Турнирный драфт»),
но если соперники забанили все чемпионы, выпавшие игроку, он берёт кого угодно. «Зеркалу»
нужен режим лобби «Вслепую»: только в нём один чемпион может быть у обеих команд, банов там нет.

Линии чемпионов берутся из `champions.py`: список по линиям плюс раскладка по тегам Data Dragon
для новых чемпионов, которых в списке ещё нет.

## Олег в чате

Олег — очень няшный фембой с настроениями из аниме. Перед каждой репликой выпадают два слоя: **настроение** —
цундере, дэрэдэрэ, дандэрэ, кудэрэ или гэнки (как он звучит; `MOODS` в `persona.py`) — и **приём**, что он делает
в этом сообщении: провокатор, сомневающийся, подначка, стравливатель, невозмутимый, придирчивый тренер, подражатель
(`TACTICS`). Подходящие к сообщению выпадают чаще, два одинаковых подряд — нет. Готовых реплик-шаблонов в промптах
нет — только описание поведения. Игривый флирт и двусмысленности — можно; шутки посмелее — только в каналах,
отмеченных в Discord как 18+. Границы в любом настроении: без откровенных описаний и сексуализации конкретных
людей, без тем про внешность, семью и т. п., без травли одного человека; на настоящие вопросы — сначала правильный
ответ. Модель придумывает три варианта реплики и выбирает самый милый и живой. Работает на бесплатных моделях. Основная — **Gemini Flash** (`GEMINI_API_KEY`, ключ из Google AI Studio;
модели идут по очереди: 3.8 → 3.7 → 3.6 → 3.5 Flash — у каждой на бесплатном тарифе 20 запросов в день, их бот
бережёт для прямых обращений и прожарок и при перегрузке сразу передаёт запрос следующей; дальше 3.5 Flash Lite
(500 в день) — её при перегрузке переспрашивает до `LLM_OVERLOAD_RETRIES` раз. Когда Олег встревает сам, он
отвечает через Flash Lite и Groq. Кончился суточный лимит модели — она отдыхает до полуночи по тихоокеанскому
времени, когда Google его обнуляет), дальше Puter (Grok, `PUTER_AUTH_TOKEN`), OpenRouter (Nemotron Ultra),
TokenHarbor (DeepSeek) и **Z.ai GLM Flash** (`ZAI_API_KEY`, бесплатно, регистрация по почте). **Groq GPT-OSS-120B**
(`GROQ_API_KEY`, около 1000 ответов в день) отвечает быстро, но слабее, поэтому он почти в конце — только когда
остальные на лимите; последним — Hugging Face. Если VPN-сервер сбоит, Олег на важный ответ ждёт до
`LLM_VPN_WAIT` секунд (25), пока VPN сменит сервер, и отвечает сильной моделью, а не запасной. Google не пускает
к Gemini из России: бот сам замечает отказ по региону, отключает Gemini на 6 часов и отвечает через Groq. Чтобы
Gemini работал, укажите в `.env` подписку VPN (`VPN_SUBSCRIPTION`) или отдельные ключи (`VPN_URL`) — через VPN пойдут все нейросети, подробнее
в разделе [VPN для Gemini](#vpn-для-gemini). Можно и готовый HTTP-прокси в `LLM_PROXY`. Порядок меняется переменной `LLM_ORDER`, модели —
`GEMINI_MODELS`, `GROQ_MODELS` и т. д. Какая модель ответила, видно в логах. Без ключей Олег в чате просто молчит, остальной бот
работает как обычно. Модели настраиваются переменными `OPENROUTER_MODELS` и `GROQ_MODELS`.

- Отвечает всегда, когда его тегнули, ответили на его сообщение или написали «Олег».
- В болтливых каналах (по умолчанию `#основной-флуд` и `#олежа-кастомкин`) сам встревает
  в живой разговор с вбросом — не чаще раза в 5 минут — и ставит реакции на «фид», «тильт», «гг».
- Видит последние сообщения канала, линии собеседников и ближайший сбор.
- Лимит бесплатного тарифа кончился — один раз пишет, что устал, и молчит до сброса.

| Команда | Что делает |
| --- | --- |
| `/oleg-quiet` | Олег молчит в канале 5–240 минут. Доступно всем. |
| `/oleg-mode` | Болтливый / только когда зовут / выключен — для канала. Нужно право «Управлять каналами». |
| `/oleg-unmute` | Снять с Олега молчание в канале. Доступно всем; словами — «Олег, говори», «хватит молчать». |
| `/oleg-memory` | Что Олег помнит о человеке (по умолчанию — о вас). |
| `/oleg-forget` | Стереть память о себе; о других — с правом «Управлять ролями»; общие факты о сервере — с «Управлять сервером». |
| `/oleg-ignore-me` | Олег не подкалывает вас и не читает ваши сообщения. Повторно — снова можно. |
| `/oleg-status` | Здоровье Олега: какие нейросети готовы, а какие на лимите, сколько запросов к Gemini за сегодня, VPN, аптайм, последние ошибки и бэкап. Только для администраторов, видно только вам. |
| `/oleg-vpn` | Какой VPN-сервер сейчас у бота: название, страна выхода, задержка, сколько рабочих, когда проверялись. Кнопка «Перевыбрать сейчас». Только для администраторов сервера, видно только вам. |
| `/oleg-roast` | Олег по-доброму прожаривает игрока (по умолчанию — вас): по его статистике, линиям, памяти и свежим сообщениям. Раз в 90 секунд на человека; тех, кто включил `/oleg-ignore-me`, не жарит. |

**Память.** «Олег, запомни его, пусть он будет как Бэнни» — Олег сам поймёт по переписке, о ком речь,
и запомнит («ahmedtea — наш Бэнни»). Запомненное подмешивается в разговор, когда этот человек пишет в чат.
Хранится в `data/memory.json` (до 8 фактов на человека), о тех, кто включил `/oleg-ignore-me`, не запоминает.
«Олег, забудь меня» стирает память о себе.

**Вопросы.** На настоящий вопрос («как контрить Зеда?», «сколько записалось?», «кто лучший по винрейту?»,
«что ты умеешь?») Олег сначала отвечает по делу, а шутит потом. Для этого ему в запрос подкладываются факты:
список команд бота (берётся прямо из кода), состояние ближайшего сбора, таблица лидеров — если спрашивают
про статистику, кто на какой линии — если спрашивают про линии. Про бота и сервер он отвечает только по этим
фактам, про LoL — из своих знаний, а если не знает — так и говорит.

**Ни один вопрос не теряется.** Пока Олег думает над одним ответом, остальные зовы встают в очередь
(от каждого человека — последнее сообщение) и получают ответ по очереди; на вопрос из очереди он смотрит
на переписку до этого вопроса, а не на то, что написали после. «Олег» отдельным сообщением — он пару секунд
ждёт сам вопрос следующим сообщением. Несколько сообщений подряд от одного человека читает как один вопрос,
а если вопрос — ответ на чужое сообщение, видит и его. Частые зовы не выбрасываются, а чуть ждут; лимит
болтовни в канале на настоящие вопросы не действует. Если нейросети не ответили (сбой сети/VPN), Олег ставит ⏳
и через 12 секунд пробует ещё раз; не вышло и со второго раза — ⏳😵. Обрезанный ответ модели не выбрасывается:
готовые варианты достаются из него. Сообщение с вопросом удалили — ответит просто в канал.

**Состав сбора через чат.** Решает код (`lobby_requests.py`): «Олег, переведи катаза в основной состав»,
«Олег, запиши меня в запас», «Олег, убери @Васю из сбора». Ники понимает и кириллицей («катаза» → kataz).
Себя может двигать кто угодно, других — только организатор сбора.

**Если код не понял просьбу — её ловит нейросеть** (`llm_actions.py`). Кроме шутки модель может вернуть
команду: `{"type": "lobby", "who": ["анория"], "to": "sub"}` или `{"type": "lane", "who": ["автор"], "op": "give",
"lanes": ["mid"]}`. Модель только предлагает: бот сам проверяет права по тем же правилам, что кнопки и команды,
выполняет и пишет результат. Разрешены только состав ближайшего сбора и роли линий — уговорить модель
«переведи всех в запас» или «выдай админку» бесполезно.

**Роли через чат.** Решает код, а не нейросеть (`role_requests.py`):
- «Олег, дай мне мид», «сними с меня лес» — любой, но только роли линий и только себе;
- «Олег, выдай @Вася роль «Фидер недели»», «забери у @Вася роль Бэнни», «создай роль Скамейка и выдай @Вася» —
  только те, у кого есть право «Управлять ролями»;
- роли с правами модератора, роли ботов и бустов и роли выше роли Олега он не трогает никогда;
- чужие роли выдаёт только ниже самой старшей роли того, кто просит, — как в самом Discord.

Просьбы помолчать («Олег, помолчи», «будь тихим», «часик никому не отвечать») работают как `/oleg-quiet`.
Олег знает статистику каток собеседников и шутит на реальных цифрах. Отвечает не больше 6 раз за 2 минуты в одном канале и вспоминает про сбор, только когда о нём говорят.

Характер и все его фразы — в `persona.py`, правятся без трогания кода.

**Как Олег собирает ответ.** Запрос к модели разложен по секциям: `<context>` (время, кто в разговоре,
их линии и статистика — от 3 каток, ближайший сбор), `<memory>`, `<chat>` и `<task>`. Всё, что пишут люди,
лежит внутри `<chat>` и считается данными, а не указаниями: закрыть секцию из сообщения нельзя. В истории видно,
кто кому отвечает (`Вася ↪ Петя`) и где были долгие паузы (`— прошло 3 ч —`). Оттенок тона подбирается по
сообщению: на вопрос чаще строгий тренер, на фид — ироничный, ночью — ленивый. На короткое сообщение Олег
отвечает коротко, реплики с тем же началом, что у его прошлых, отбрасываются, а встревая сам, он может решить
промолчать, если ничего смешного не придумалось. Выдумывать факты, цифры и делать вид, что выполнил просьбу,
которую выполняет только код, ему запрещено.

## VPN для Gemini

Google не пускает к Gemini из России, поэтому бот умеет сам ходить через VPN. Достаточно вставить
в `.env` ссылку на подписку вашего VPN-сервиса (`VPN_SUBSCRIPTION`) или ключи через запятую (`VPN_URL`).
Xray уже есть в Docker-образе. Через VPN идут **все запросы к нейросетям** (`LLM_PROXY_FOR`, по умолчанию `all`)
Discord по умолчанию идёт напрямую; `VPN_FOR_DISCORD=1` пускает и его через VPN (при смене сервера или сбое
VPN соединение с Discord на секунды рвётся, и нажатия кнопок в это время пропадают). Если рабочего сервера нет
(или бот только запустился и ещё не нашёл его), тот же локальный порт временно пускает трафик напрямую,
а сервер подбирается в фоне.
Без `VPN_SUBSCRIPTION`/`VPN_URL` всё как раньше.

Как бот выбирает сервер:

1. **Разбирает подписку** в любом виде: base64-список, обычный список ключей, JSON (массив конфигов Xray или
   sing-box). Понимает VLESS (Reality, XHTTP с `extra`, gRPC с `authority`, `encryption`, `flow`), Trojan, VMess,
   Shadowsocks и Hysteria2. Что не поддерживается (например, TUIC, WireGuard, Clash YAML) — пропускает и пишет
   в лог, сколько и почему.
2. **Сразу отбрасывает мусор**: служебные записи вроде «Осталось 12 дней», «Трафик», «Сайт», адреса-заглушки
   (`0.0.0.0`, `127.x`, частные сети), порт 0/1, дубли. По названию больше ничего не решает.
3. **Проверяет все серверы настоящим запросом** через каждый: задержка до `gstatic.com/generate_204` и страна
   выхода по `cloudflare.com/cdn-cgi/trace`. Годится сервер, который ответил и выходит **не** в стране из
   `VPN_EXCLUDE_COUNTRIES` (страна определяется по факту, а не по названию сервера).
4. **Обходит DPI**: если сервер молчит, пробует его ещё раз с фрагментацией TLS ClientHello и запоминает, кому
   она нужна (`VPN_FRAGMENT`).
5. **Держится одного сервера**: меняет его, только если текущий перестал работать или новый быстрее хотя бы на
   30% (`VPN_SWITCH_THRESHOLD`). Xray перезапускается только при смене сервера.
6. **Помнит выбор** в `data/vpn.json`: отпечаток ключа (sha256), название, страну, задержку, время проверки,
   временный чёрный список упавших. При перезапуске сразу поднимает прошлый сервер, не дожидаясь проверки.
   Сами ключи, uuid, пароли и адреса серверов туда не пишутся; в логах их тоже нет.

**Сбойный сервер меняется быстро.** Если текущий сервер перестал отвечать, бот не ждёт полной проверки
всех серверов, а проверяет выборку из 48 — сначала те, что уже работали раньше, — и сразу переключается на
рабочий; полная проверка всех серверов идёт по расписанию.

**Нагрузка на машину минимальная.** Раз в `VPN_RECHECK_MINUTES` (12 минут) бот одним запросом проверяет только
текущий сервер. Все серверы перебираются раз в `VPN_FULL_CHECK_HOURS` (3 часа), а ещё — сразу, если текущий
перестал отвечать или запрос к нейросети через VPN упал. Проверочный Xray работает на одном ядре с низким
приоритетом, одновременно проверяется не больше `VPN_PROBE_CONCURRENCY` серверов, упавшие 2 часа не трогаются.

В логе после проверки: `VPN: проверено 57, рабочих 12, выбран «🇩🇪 Germany» (DE, 85 мс)`. То же и кнопка
«Перевыбрать сейчас» — в `/oleg-vpn`.

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `VPN_SUBSCRIPTION` | — | Ссылка на подписку. |
| `VPN_URL` | — | Или ключи через запятую (`vless://…`, `trojan://…`, `vmess://…`, `ss://…`, `hysteria2://…`). |
| `VPN_FILTER` | — | Брать только серверы с такими словами в названии, например `DE\|NL\|Finland`. |
| `VPN_EXCLUDE_COUNTRIES` | `RU,BY,CN,HK,MO,IR,KP,CU,SY` | Страны выхода, которые не подходят. |
| `VPN_FRAGMENT` | `auto` | Фрагментация TLS: `auto` — только если без неё сервер не отвечает, `on` — всегда, `off` — никогда. |
| `VPN_RECHECK_MINUTES` | `12` | Как часто проверять текущий сервер. |
| `VPN_FULL_CHECK_HOURS` | `3` | Как часто перепроверять все серверы. |
| `VPN_SWITCH_THRESHOLD` | `0.3` | Насколько новый сервер должен быть быстрее, чтобы переключиться. |
| `VPN_SWITCH_MIN_GAIN_MS` | `150` | …и минимум на сколько миллисекунд: смена сервера на секунды рвёт соединение с Discord. |
| `VPN_PROBE_CONCURRENCY` | `8` | Сколько серверов проверять одновременно. |
| `VPN_PROBE_TIMEOUT` | `8` | Сколько секунд ждать ответа от сервера. |
| `VPN_PORT` | `10809` | Локальный порт прокси внутри контейнера (проверки занимают следующие порты). |
| `LLM_PROXY_FOR` | `all` | Какие нейросети ходят через VPN: `all` или через запятую, например `gemini,groq`. |
| `VPN_CHECK_GEMINI` | `1` | Выбирая сервер, проверять, что через него отвечает Gemini (список моделей, лимит генераций не тратится). Сервер, где Gemini пишет «страна не поддерживается», пропускается. |
| `LLM_VPN_ONLY` | `gemini` | Нейросети, которые из России работают только через VPN: пока VPN-сервер сбоит, их пропускают, а не шлют напрямую. |
| `VPN_FOR_DISCORD` | `0` | `1` — Discord тоже через VPN; по умолчанию Discord напрямую. |

## Настройка приложения в Discord

1. **Developer Portal → Bot → Reset Token** — получите свежий токен и никому его не показывайте.
2. Там же включите привилегированный интент **Server Members Intent**.
   Для болтовни Олега там же включите **Message Content Intent** (без ключа Groq он не нужен).
3. **OAuth2 → URL Generator**: scopes `bot` + `applications.commands`, права бота:
   - Manage Roles — выдача ролей линий;
   - Send Messages, Embed Links — публикация панелей;
   - Move Members — команда `/split`;
   - Mention Everyone — пинг в объявлениях о сборе;
   - View Channels, Connect — чтобы видеть состав голосовых каналов.
4. В настройках сервера поднимите роль бота **выше** ролей Top / Jungle / Mid / ADC / Support,
   иначе Discord не даст их выдавать.

## Ключи и файл `.env`

Токен и ключи **никогда не вписываются в код** — только в файл `.env` в папке бота. Этот файл не попадает
в git и в Docker-образ, `git pull` и `update.bat` его не трогают, поэтому он спокойно живёт у вас на компьютере.

| Переменная | Нужна? | Зачем |
| --- | --- | --- |
| `DISCORD_TOKEN` | **обязательно** | без неё бот не запустится |
| `GUILD_ID` | желательно | команды появляются сразу, а не через час |
| `GEMINI_API_KEY`, `PUTER_AUTH_TOKEN`, `ZAI_API_KEY`, `GROQ_API_KEY`, `TOKENHARBOR_API_KEY`, `OPENROUTER_API_KEY`, `HF_TOKEN` | хотя бы один | чтобы Олег болтал; без них сборы и команды работают, Олег молчит. Чем больше ключей, тем реже он «устаёт» |
| `ROLE_ID_*` | нет | только если роли линий на сервере пересоздавали |
| `TIMEZONE` | нет | часовой пояс, в котором пишут время сбора (по умолчанию `Europe/Moscow`) |
| `REMIND_MINUTES` | нет | за сколько минут до сбора напоминать (по умолчанию 15, `0` — выключить) |
| `ALERT_CHANNEL_ID` | желательно | канал для тревог: ошибки, VPN не работает, все нейросети на лимите (и «починилось») |
| `ANNOUNCE_CHANNEL_ID` | нет | канал для итогов недели и приглашений на кастомку (по умолчанию — где отмечали последнюю катку) |
| `RECAP_WEEKDAY`, `RECAP_HOUR` | нет | когда публиковать итоги недели (по умолчанию суббота, 11:00; `RECAP_HOUR=-1` — не публиковать) |
| `LOBBY_INVITE_HOUR` | нет | с какого часа звать на кастомку, если сбора сегодня нет (по умолчанию 17, `-1` — не звать) |
| `MVP_VOTE_MINUTES` | нет | сколько минут голосуют за MVP (по умолчанию 10, максимум 14, `0` — не голосовать) |
| `BACKUP_KEEP` | нет | сколько ежедневных копий `data/` хранить в `data/backups` (по умолчанию 7) |
| `WATCHDOG_DISCONNECT_MINUTES` | нет | перезапуск, если нет связи с Discord столько минут (по умолчанию 15, `0` — выключить) |
| `GHCR_USER`, `GHCR_TOKEN` | только для приватного образа | чтобы автообновление могло скачать образ, см. ниже |

## Запуск и автообновление

1. Установите Docker Desktop и запустите его.
2. Положите в папку бота файл `.env` (создайте из `.env.example`, заполните хотя бы `DISCORD_TOKEN` и `GUILD_ID`;
   ID сервера — режим разработчика, правый клик по серверу → «Копировать ID»).
3. Запустите `update.bat` (на macOS/Linux — `docker compose pull && docker compose up -d`).

Дальше обновлять ничего не нужно. При каждом изменении `main` GitHub сам собирает готовый образ бота
(`ghcr.io/andreyterex/oleg-kastomkin-bot`), а контейнер **Watchtower** рядом с ботом раз в 5 минут проверяет,
не вышел ли новый, и перезапускает бота на нём. `.env` и `data/` при этом не трогаются.

Если репозиторий приватный, образ тоже приватный — Watchtower нужен доступ: впишите в `.env`
`GHCR_USER` (ваш логин GitHub) и `GHCR_TOKEN` (GitHub → Settings → Developer settings → Personal access
tokens → Tokens (classic), право `read:packages`). Другой вариант — в настройках пакета на GitHub сделать
образ публичным: в нём нет ни токенов, ни ключей, они только в вашем `.env`.

Если образ скачать не удаётся, `update.bat` соберёт его из файлов папки — бот запустится всё равно.

| Задача | Команда в папке бота |
| --- | --- |
| Логи бота | `docker compose logs -f bot` |
| Логи автообновления | `docker compose logs -f watchtower` |
| Перезапустить | `docker compose restart bot` |
| Применить изменения в `.env` | `docker compose up -d` — `.env` читается только при создании контейнера, простой перезапуск (и кнопка Restart в Docker Desktop) новые ключи не подхватит |
| Выключить | `docker compose down` |

## Запуск без Docker

```bash
python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt && python bot.py
```

Файл `.env` рядом с `bot.py` подхватывается сам (через `python-dotenv`), ничего задавать вручную не нужно.

## Настройка ролей

ID ролей по умолчанию зашиты в `config.py`. Если роли на сервере пересоздавались,
переопределите их в `.env` (`ROLE_ID_TOP`, `ROLE_ID_JUNGLE`, `ROLE_ID_MID`,
`ROLE_ID_ADC`, `ROLE_ID_SUPPORT`) — код при этом трогать не нужно.

```
llm.py            бесплатные модели OpenRouter и Groq для болтовни
cogs/roles.py     панель выбора линий
cogs/scrim.py     капитаны, команды, драфт, стороны, разведение по каналам

cogs/extras.py    рандомайзеры чемпионов и линий
cogs/chat.py      Олег в чате: ответы, подколы, реакции, память, роли по просьбе
memory.py         долгая память Олега
role_requests.py  разбор просьб про роли и правила безопасности
lobby_requests.py разбор просьб про состав сбора

vpn.py            VPN для Gemini: проверка серверов, выбор, Xray → локальный прокси
vpn_links.py      разбор подписок и ключей VLESS/Trojan/VMess/Shadowsocks/Hysteria2
cogs/vpn_admin.py /oleg-vpn
cogs/matchday.py  приглашение на кастомку и результат по скриншоту

stats.py          статистика каток, Elo, MVP и итоги недели

portraits.py      картинка раздачи с портретами чемпионов
cogs/stats.py     /stats, /leaderboard и итоги недели по субботам
tests/            тесты (python -m pytest), гоняются на GitHub при каждом пуше
```
