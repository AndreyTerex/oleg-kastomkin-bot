# Запуск бота «Олег Кастомкин» у друга

Бот ведёт сборы на кастомки и скримы на сервере «ПОДГОТОВКА К WORLDS» и болтает в чате как Олег.
Настраивать ничего не нужно: токен бота, ключи нейросетей, VPN и подключение к общей базе лежат
в файле `.env` в папке бота. Нужен только Docker и включённый компьютер.

## Как бот уживается на двух компьютерах

Статистика, коины, сборы и память Олега хранятся в **общей базе** (строка `DATABASE_URL` в `.env`),
поэтому бота можно держать запущенным и у владельца, и у вас одновременно:

- работает только один — тот, кто первым подключился к базе;
- второй сам ждёт в резерве и в Discord не заходит. В логах у него раз в 5 минут строка
  `Общей базой владеет другой экземпляр бота … Жду в резерве` — это нормально;
- стоит первому выключиться, резервный сам подхватывает работу со всеми данными
  (через несколько секунд, самое большее через 3 минуты).

То есть ничего согласовывать не нужно: запустили — и ваш бот страхует основной.

Если база временно недоступна (пропал VPN, нет связи с облаком), бот, который работал последним,
продолжает на своей копии данных и сам переносит сделанное в базу, когда она вернётся.
Резервный бот в это время просто ждёт — так в Discord не появятся два Олега.

## VPN

Если у вас в России облачная база не отвечает напрямую, боту нужен VPN. Подойдёт любой из вариантов —
бот перебирает их сам, по порядку:

1. **Подписка VPN в `.env`** (`VPN_SUBSCRIPTION`) — если владелец её туда вписал, ничего делать не нужно.
2. **VPN на вашем компьютере** (v2rayN, Hiddify, Clash, NekoRay…) — просто держите его включённым, бот сам его
   найдёт. В логах: `VPN: найден VPN этого компьютера`. Если VPN включён, а бот пишет `VPN-клиента на этом
   компьютере не видно`, включите в настройках VPN-клиента «Разрешить подключения из локальной сети»
   (Allow connections from LAN) и перезапустите бота.
3. **Обычный интернет компьютера** — если ни того, ни другого нет (или VPN включён в режиме TUN).

## 1. Поставить Docker Desktop (один раз)

Скачать с [docker.com](https://www.docker.com/products/docker-desktop/), установить, запустить.
Подождать, пока значок кита в трее перестанет мигать и появится надпись «Docker Desktop is running».
При установке на Windows он может попросить перезагрузку — соглашайтесь.

Чтобы бот сам поднимался после перезагрузки компьютера, включите в Docker Desktop:
Settings → General → **Start Docker Desktop when you sign in**.

## 2. Распаковать архив

Распакуйте куда угодно, например в `C:\oleg-bot`. Внутри должна быть папка `oleg-bot` с файлами
`bot.py`, `update.bat`, `docker-compose.yml`, **`.env`** и папками `cogs`, `data`.

Файл `.env` в Проводнике выглядит как файл без имени — это нормально. Если его в папке нет,
бот не запустится: попросите `.env` у владельца и положите рядом с `docker-compose.yml`.

Бот у вас уже был? Распакуйте поверх **с заменой файлов** — папку `data` не удаляйте.

## 3. Запустить

Дважды щёлкните **`update.bat`** в папке `oleg-bot`. Он сам проверит Docker, скачает готовый образ бота
(или соберёт его, если скачать не вышло), запустит бота вместе с автообновлением и покажет логи.
Окно логов можно закрыть — бот продолжит работать.

Дальше бот обновляется сам: рядом с ним работает **Watchtower**, который раз в 5 минут проверяет на GitHub
новую версию и перезапускает бота на ней. Ни логин, ни токен GitHub для этого не нужны — образ бота публичный.
`update.bat` сам проверяет, что Watchtower запустился, и в конце показывает оба контейнера.

На macOS/Linux то же самое — в терминале в папке бота:

```bash
docker compose pull && docker compose up -d
```

## 4. Проверить, что работает

В логах будет один из двух вариантов — оба правильные.

**Ваш бот основной** (у владельца бот выключен):

```
Общая база: экземпляр oleg:… получил право записи
Бот в сети: Олег Кастомкин#5758 (серверов: 1)
```

После этого в Discord бот «в сети», команды `/custom`, `/scrim`, `/ping` работают, Олег отвечает в чате.

**Ваш бот в резерве** (у владельца бот работает):

```
Общей базой владеет другой экземпляр бота: oleg:…, … Жду в резерве, проверяю раз в 15 с.
```

Так и должно быть: ваш бот подхватит работу, когда основной выключится.

**Автообновление.** В конце `update.bat` (или по команде `docker compose ps`) должны быть два контейнера
со статусом `running` / `Up`: `lol-scrim-bot` (сам бот) и `oleg-watchtower` (автообновление).
Если `oleg-watchtower` нет или он не `Up` — запустите `update.bat` ещё раз, а если не помогло,
посмотрите `docker compose logs watchtower` и пришлите владельцу. Watchtower обновляет и резервного
бота, так что у вас всегда та же версия, что и у владельца.

## Что может понадобиться дальше

| Задача | Команда в папке бота |
| --- | --- |
| Посмотреть логи | `docker compose logs -f` |
| Работают ли бот и автообновление | `docker compose ps` |
| Логи автообновления | `docker compose logs -f watchtower` |
| Обновить прямо сейчас, не дожидаясь Watchtower | дважды щёлкнуть `update.bat` |
| Перезапустить, если подвис | `docker compose restart` |
| Выключить бота (и автообновление) | `docker compose down` |
| Включить снова | `docker compose up -d` |

**Папку `data` не удалять.** В ней копия данных на случай, если база недоступна, и служебные файлы бота.

**Архив и `.env` никому не пересылайте.** Внутри токен бота, ключи нейросетей, подписка VPN и пароль базы.

## Если что-то не так

| Что видно | Что делать |
| --- | --- |
| `Docker is not running` / `Cannot connect to the Docker daemon` | Запустите Docker Desktop и подождите надписи «running». |
| `WARNING: Watchtower is not running` | Автообновление не запустилось. Запустите `update.bat` ещё раз; не помогло — `docker compose logs watchtower` владельцу. |
| `.env was not found` | В папке нет `.env` — попросите его у владельца и положите рядом с `docker-compose.yml`. |
| `Discord отклонил токен` | Токен сброшен — нужен свежий `.env` от владельца. |
| `Общей базой владеет другой экземпляр бота` | Всё нормально: работает бот владельца, ваш в резерве. |
| `Общая база не ответила вовремя — перезапуск …` | Базе не хватает VPN — включите VPN на компьютере (см. раздел «VPN»). Бот повторяет сам, всё реже. |
| `Общая база недоступна (…). Без неё не запускаюсь` | База временно недоступна, а ваш бот — резервный. Он ждёт базу сам, делать ничего не нужно. |
| `Работаю без общей базы, на локальной копии` | База недоступна, бот работает на своей копии и сам вернётся на базу. Делать ничего не нужно. |
| `VPN: … пока хожу напрямую` | Рабочего VPN-сервера нет — бот работает через обычный интернет. Не работает только Gemini, Олег отвечает другими нейросетями. |
| `Нет связи (…) — перезапуск через N с` | Нет интернета. Бот перезапускается сам, всё реже, пока связь не вернётся. |
| Олег молчит, в логах `Лимит …` или `Не удалось обратиться к …` | Нейросети на лимите или недоступны. Сборы и команды при этом работают. |
| `Сообщения приходят без текста` | В Developer Portal выключен Message Content Intent — это исправляет владелец. |

Описание всех возможностей бота — в `README.md`.
